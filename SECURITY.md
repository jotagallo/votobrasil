# Security Policy

## Reporting a vulnerability

Please **do not open a public issue** for security problems.

Use GitHub's private reporting: **Security → Report a vulnerability** on this repository
(<https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability>).
Include the affected component, steps to reproduce, and the impact you observed.

You can expect an acknowledgement within 3 business days and a status update within 10 business
days. Fixes are released on `main` and deployed continuously; we will credit you in the advisory
unless you prefer to stay anonymous. Please allow a reasonable time to fix the issue before
disclosing it publicly.

## Supported versions

Only the latest commit on `main` (what runs in production) is supported.

## Scope

In scope:

- The API (`apps/api`), the web app (`apps/web`) and the shared/ETL packages.
- The infrastructure code in `infra/` and the CI/CD workflows in `.github/`
  (for example: overly broad IAM permissions, a way to bypass the CloudFront-only origin
  protection, workflow injection, or a way to exfiltrate credentials).
- The Docker image built from the `Dockerfile`.

Out of scope:

- Errors or disagreements about the electoral data itself. The data comes from the official
  TSE/IBGE open data and is processed by the documented methodology; report these as regular
  issues.
- Vulnerabilities in third-party services (AWS, GitHub, Umami Cloud, TSE, IBGE) or in upstream
  dependencies without a demonstrated impact on this project.
- Volumetric denial of service, social engineering, and physical attacks.
- Reports from automated scanners without a working proof of concept.

## How secrets are handled

This repository is public and contains **no secrets**. Anything that appears to be a credential in
the history or the tree is a bug: please report it.

- Deployments authenticate to AWS with short-lived credentials through GitHub OIDC; there are no
  static AWS access keys. The deploy role only trusts the `production` GitHub environment of this
  repository.
- The only runtime secret is a random value shared by CloudFront and the origin
  (`ORIGIN_VERIFY_SECRET`). It is generated by Terraform and lives only in the encrypted remote
  Terraform state and in the AWS service configuration.
- Terraform state, `.env` files and `*.tfvars` are git-ignored; CI runs a secret scan (gitleaks)
  and a dependency audit on every change.
- Values used at build time by the web app (`VITE_*`) are public by design and end up in the
  browser bundle.

Details are in [`infra/README.md`](infra/README.md).
